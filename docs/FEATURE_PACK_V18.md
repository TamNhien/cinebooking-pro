# CineBooking Pro V18 - Dynamic Pricing

V18 adds a configurable ticket-pricing engine while preserving the existing `showtime.base_price` and `seat.price_modifier` model.

## Price formula

For each seat:

```text
price_before_dynamic = showtime.base_price + seat.price_modifier
final_price = max(0, price_before_dynamic + sum(matching rule adjustments))
```

- `FIXED`: adds/subtracts a fixed VND amount.
- `PERCENT`: adds/subtracts a percentage of `price_before_dynamic`.
- Matching active rules are cumulative.
- Percentage rules do not compound on one another; they all use the same `price_before_dynamic` base.
- The final seat price is rounded to whole VND.
- The final value is copied into `booking_seat.price` when the booking is created. Editing/deleting a pricing rule later never rewrites historical booking prices.

## Rule filters

Admin can combine any of these filters:

- cinema
- auditorium
- movie
- seat type: STANDARD / VIP / COUPLE / ACCESSIBLE
- ISO weekday: 1=Monday ... 7=Sunday
- local showtime time range, including cross-midnight ranges such as 20:00 -> 02:00
- valid-from / valid-to date
- priority
- active/inactive

A blank filter means "all" for that dimension.

## Admin UI

Open:

```text
http://localhost/admin/pricing
```

Features:

- create / edit / activate / pause / delete pricing rules
- positive surcharge or negative off-peak discount
- filter by cinema, room, movie and seat type
- choose weekdays and time window
- choose validity dates
- preview exact price for a real showtime + seat
- preview lists every applied rule and its amount

Two inactive example rules are inserted by V18 so current ticket prices do not change automatically.

## Customer booking UI

Seat-map prices are now generated by the same pricing engine used during booking creation. A selected seat displays its dynamic adjustment, and the order summary shows the aggregate dynamic component when non-zero.

This removes a common inconsistency where the UI can display one price while the backend stores another.

## Database

Migration:

```text
V18__dynamic_pricing.sql
```

New table:

```text
pricing_rule
```

Historical `booking_seat.price` remains the price snapshot/source of truth for existing bookings.

## Timezone

Default:

```env
PRICING_TIME_ZONE=Asia/Ho_Chi_Minh
```

Rules are evaluated against the showtime converted from UTC to this local timezone.

## Upgrade

Do not delete the current PostgreSQL volume.

```powershell
docker compose up -d --build --force-recreate backend-1 backend-2 frontend nginx
```

Verify:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\diagnose-v18.ps1
```

Functional smoke test:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\test-v18.ps1
```

The smoke test creates a temporary +1,234 VND rule, verifies that preview changes by exactly 1,234 VND, deletes the rule, and verifies that the price returns to the baseline.
